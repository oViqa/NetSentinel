## Overview

NetSentinel is a student-built network intrusion detection system (IDS) based on machine
learning. It learns to tell benign network flows from Denial-of-Service (DoS) traffic using
the CICIDS2017 dataset, then shows its predictions in a small Streamlit dashboard.

```text
  CICIDS2017 flows (CSV)
           |
           v
  +----------------+     +------------------+     +------------------+
  |  Inspect and   | --> |  Split, then     | --> |  Train and       |
  |  clean         |     |  preprocess      |     |  evaluate        |
  +----------------+     +------------------+     +------------------+
                                                            |
                                                            v
                                                  +------------------+
                                                  |  Streamlit       |
                                                  |  dashboard       |
                                                  +------------------+
```

### What version 1 is (and is not)

Version 1 is one honest experiment on recorded flows. The model learns from labelled
CICIDS2017 flows, is evaluated on a held-out test set, and its mistakes are analysed
and explained.

It is **not** a live monitoring tool. The claim we aim to support is "detects DoS-like
traffic in this dataset", not general real-world intrusion detection.

## Pipeline

1. **Understand the data.** Download and inspect the CICIDS2017 files, build a feature
   glossary from the CICFlowMeter definitions, and pick the DoS attacks, files, alert
   definition and metrics.
2. **Clean.** Strip leading spaces from column names, handle `Infinity` and `NaN` in rate
   columns, and remove duplicate rows. Fixed structural cleanup is applied consistently.
3. **Check for shortcuts.** Investigate IP addresses, timestamps, flow IDs and destination
   ports, which can reveal collection conditions instead of attack behaviour.
4. **Split.** Train, validation and test sets. Stratification keeps class proportions;
   grouping or time boundaries are used where related sessions could cross the split.
5. **Preprocess.** Imputers and any other learned steps live in a scikit-learn `Pipeline`
   and are fitted on training data only.
6. **Model.** A `DummyClassifier` baseline first, then a Decision Tree and a Random Forest.
   Settings are tuned on the validation set.
7. **Evaluate.** Final run on the untouched test set: precision, recall, F1-score,
   false-positive rate and a confusion matrix, always with sample counts.
8. **Error analysis.** Group false alarms and missed attacks by attack type and traffic
   characteristics, and inspect related captures in Wireshark.
9. **Dashboard.** Upload a CSV, validate its columns, run predictions, browse a filterable
   table and export the results.

## Evaluation rules

These are the rules we hold ourselves to, because inflated scores are easy to get on
this dataset.

- **Beat the baseline, not just a number.** If 80% of flows are benign, always predicting
  "benign" scores 80% accuracy and catches nothing.
- **Keep the boundary.** Nothing learned from validation or test data reaches training:
  no duplicates across splits, no preprocessing fitted on the full dataset.
- **Protect the final test.** No tuning on it. Once it influences a decision, it is no
  longer an independent evaluation.
- **No day shortcut.** Monday in CICIDS2017 is benign only. Taking all benign examples from
  Monday and all attacks from another day would let the model learn the capture day.
- **Report counts.** Percentages always come with the number of samples behind them.
- **Thresholds are a choice.** `predict_proba` outputs are not necessarily calibrated
  probabilities; the alert threshold is picked deliberately using the precision-recall curve.

## Getting started

Installation and run instructions will be completed once the project structure is in
place. The planned setup:

```bash
git clone <repo-url>
cd netsentinel
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

The dashboard will run with:

```bash
streamlit run app.py
```

### Data

The CICIDS2017 CSVs and trained models are **not** stored in this repository (they are
too large for ordinary Git and are listed in `.gitignore`). Download the dataset from the
[official page](https://www.unb.ca/cic/datasets/ids-2017.html); the exact files used and
how to regenerate every output will be documented here.
